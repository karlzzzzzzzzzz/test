# 迷宫寻路（Maze）需求文档与实现说明

> 第 14 款小游戏 · 路由 `/maze` · 纯逻辑引擎 `src/game/MazeEngine.js` · 页面壳 `src/pages/Maze.jsx`

## 一、需求概述

### 1.1 背景

现有游戏库里已有翻牌配对、拼图、2048、推箱子、黑白棋、扫雷等，但缺少「空间寻路」类玩法。迷宫寻路用一张每局随机生成的完美迷宫，把「方向判断 + 路径记忆 + 步数控制」压缩成一局 1～3 分钟的轻量挑战，适合手机单手操作，也能用键盘完整游玩。

### 1.2 目标

- 每局随机生成、且**保证起点到终点连通**，不会出现无解。
- 用**步数**作为核心评价维度：参考步数由 BFS 最短路给出，走弯路要扣分。
- 触控（单指滑动 / 点按相邻格）与键盘（方向键）双通道等价，读屏用户可完整游玩。
- 切后台、失焦立即暂停并冻结计时；生成过程与失败都有明确反馈。

### 1.3 非目标

- 不做多人对战、不做关卡编辑器、不做云端排行榜。
- 不引入第三方依赖；不使用 Canvas / WebGL，盘面为 DOM 网格。

## 二、玩法规则

| 编号 | 功能点 | 规则与数值 |
| --- | --- | --- |
| F1 | 迷宫生成 | DFS 回溯（递归回溯）生成完美迷宫：初始每格四面是墙，随机选未访问邻格凿墙，直到全格访问；任意两格间路径唯一 |
| F2 | 起点 / 终点 | 起点固定左上角（索引 0），终点固定右下角（索引 n²−1） |
| F3 | 连通性校验 | 生成后用 BFS 复核首尾连通；不通则 `start()` 抛错，页面进入错误态 |
| F4 | 参考步数 par | BFS 最短路长度（步数），写入快照，用于计分与 HUD 展示 |
| F5 | 三档难度 | 轻松 5×5 / 120s / 基准 500；挑战 6×6 / 150s / 基准 800；专家 7×7 / 180s / 基准 1200 |
| F6 | 移动 | 四方向移动一格；目标方向有墙或越界视为撞墙，不计步、不移动，播报「前方是墙」 |
| F7 | 步数统计 | 每次有效移动 +1，HUD 实时显示；撞墙、提示、重走均不增加步数 |
| F8 | 走过的格子 | 用 `visited` 位图记录，盘面上以浅蓝底标出，起点默认已访问 |
| F9 | 提示 | 每局 3 次；给出当前位置沿最短路的下一个方向，目标格高亮 1.4s；不移动玩家 |
| F10 | 提示扣分 | 每次提示扣 25 分；次数用尽后按钮禁用并播报 |
| F11 | 计分公式 | `max(100, 基准分 − max(0, 步数−par)×3 − floor(用时秒)×2 − 提示次数×25)` |
| F12 | 胜利判定 | 玩家移动到终点格即判定 `win`，结算用时、步数、提示次数与得分 |
| F13 | 超时判定 | 页面每 250ms 调 `tick()`；有效移动后开始计时，到达档位限时进入 `timeout`，得分 0 |
| F14 | 暂停 / 恢复 | `pause()` 冻结计时并拒绝移动/提示；`resume()` 以恢复时刻为新基准继续累计 |
| F15 | 双路暂停 | `visibilitychange(hidden)` 与 `window blur` 双路触发，用标记位去重，避免一次切走暂停两次 |
| F16 | 重走本局 | 保留同一张迷宫，玩家回起点，步数/用时/提示次数全部重置 |
| F17 | 换新迷宫 | 按当前难度重新生成一张迷宫（重新进入 loading → playing） |
| F18 | 移动节流 | 60ms 内的重复移动指令忽略，避免滑动与连点造成一次手势走两格 |
| F19 | 最佳记录 | 每档只保留最高分 `{score, steps, time, hints}`，仅在更高分时覆盖 |
| F20 | 累计埋点 | `plays / wins / timeouts / resets / steps / timeByLevel`，脏标记 + 1s 延迟落盘，`pagehide` 兜底 |

## 三、三态设计（加载 / 空 / 错误）

| 状态 | 触发时机 | 界面表现 | 可用操作 |
| --- | --- | --- | --- |
| 加载 | 选择难度或「换新迷宫」后 220ms 内 | 全屏遮罩 + 旋转指示器 + 「正在生成迷宫…」，`role=status` 播报 | 无（等待） |
| 空 | 本机没有任何最佳记录 | 难度列表下方虚线框：「暂无最佳记录，完成一局后自动保存」；HUD 显示 `—` | 选择难度开始 |
| 错误 | `start()` 抛错（首尾不连通 / 意外异常） | 遮罩「迷宫生成失败」+ 说明 + 「重试」「返回首页」 | 重试按上次难度重新生成 |

> 加载态用 `setTimeout(220ms)` 让浏览器先绘制遮罩再同步生成迷宫，避免生成期间界面无反馈；组件卸载或重复开局会清理定时器。

## 四、页面结构

1. **顶部栏**：返回首页链接（≥40px 高）、标题「迷宫寻路」、暂停/继续按钮（仅游戏中显示）。
2. **HUD**：四格统计——步数、参考、提示、倒计时（`role=timer`，不逐秒播报）。
3. **盘面**：`role=grid` → `role=row` → `role=gridcell` → 原生 `<button>`；墙用每格四边的绝对定位小块绘制；玩家为蓝色光点，终点为琥珀色菱形，提示目标为绿色描边。
4. **动作区**：提示（含剩余次数）/ 重走本局 / 换新迷宫；暂停时整体禁用。
5. **说明文案**：操作方式与计分提示。
6. **遮罩**：start / loading / error / paused / over 五种，均为全屏 `position: fixed`，卡片居中可滚动。

## 五、交互与无障碍

- **点按**：只能点当前位置上下左右的相邻格；点自身会播报坐标与「距终点最短 X 步」；点非相邻格播报「只能点按相邻格」，不移动。
- **滑动**：`touchstart/touchend` 计算位移，主轴位移 ≥24px 才判定方向，一次手势只产生一次移动。
- **键盘**：盘面 `onKeyDown` 拦截四个方向键直接移动（并 `preventDefault` 阻止页面滚动）；Enter / Space 播报当前格可走方向。
- **roving tabindex**：仅玩家所在格 `tabIndex=0`，其余为 `-1`；每次移动后焦点跟随玩家，Teleport 到新格。
- **aria-live**：独立视觉隐藏区 `aria-live="polite" aria-atomic="true"`；开局、移动、撞墙、提示、重置、胜利、超时、暂停、恢复均有播报，tick 刷新用动作键去重，避免 250ms 重复朗读。
- **布局**：页面 `min-height: 100svh`（兼容移动端浏览器地址栏收缩）；`overflow-x: hidden`；盘面 `max-width: 460px` 居中。
- **热区**：每格 `min-width/min-height: 40px`；≤340px 时页面与盘面去掉左右内边距，保证 7 列在 320px 下每格约 45px。
- **降级动效**：`prefers-reduced-motion: reduce` 时关闭所有过渡与旋转动画，加载指示器静态显示。

## 六、数据与存储

仅使用 2 个 localStorage 键，读写均做结构校验与异常降级：

| 键 | 结构 | 说明 |
| --- | --- | --- |
| `game-maze-best-v1` | `{ [tier]: { score, steps, time, hints } }` | 每档最高分；损坏时整体回退为空对象，写入失败仅内存展示 |
| `game-maze-stats-v1` | `{ plays, wins, timeouts, resets, steps, timeByLevel, updatedAt }` | 累计埋点；`plays/wins/timeouts/timeByLevel` 为按档位对象，`updatedAt` 为最后落盘时间 |

- 埋点采用「脏标记 + 1s 防抖」写入，`pagehide` 与页面隐藏时强制 flush，避免频繁写盘。
- 存储异常（隐私模式 / 配额满）不阻断游戏，仅在结算页提示「本局成绩未保存」。

## 七、验收标准

1. 选择任一难度后先出现加载遮罩，随后盘面出现，玩家位于左上角，终点位于右下角。
2. 同一随机源生成结果可复现；不同对局墙体不同；任意格都能从起点到达。
3. 沿 BFS 最短路走完，步数恰好等于 HUD「参考」值，并进入胜利结算。
4. 撞墙时步数不变、玩家不动，读屏播报「前方是墙，换个方向」。
5. 计时从第一次有效移动开始；到点后进入超时结算，得分为 0。
6. 暂停后方向键、点按、滑动、提示全部无效，计时不再增长；继续后从暂停处累计。
7. 切后台或窗口失焦只触发一次暂停，返回后显示「已自动暂停」。
8. 提示给出的方向与引擎最短路一致，最多 3 次，每次扣 25 分。
9. 重走本局后墙体不变、步数归零、计时归零、提示次数恢复 3 次。
10. 最佳记录只在更高分时覆盖；本机无记录时开始页显示空态文案。
11. 320 / 360 / 375 / 390 / 414 / 428 / 768 / 1024 / 1440 九档下无横向滚动、无文字小于 12px、无热区小于 40px。
12. `prefers-reduced-motion` 下无旋转动画与位移动画；键盘 Tab 序进入盘面后停在玩家格。
13. 生成失败进入错误态，点击「重试」可重新生成；返回首页链接可用。

## 八、边界与异常

| 场景 | 处理 |
| --- | --- |
| 生成结果首尾不连通 | `start()` 抛 `Error`，页面进入 error 遮罩，重试按上次难度重新生成 |
| localStorage 不可用 / 数据损坏 | 读取回退空结构；写入失败置 `saveError`，游戏继续 |
| 60ms 内连续移动 | 第二次返回 `ignored`，不计步、不播报 |
| 非 playing 状态收到移动/提示 | 直接忽略，不改变快照 |
| 暂停时窗口再次失焦 | `onBlur` 发现 visibility 标记已置位则跳过，保证只暂停一次 |
| 提示次数用尽 | `hint()` 返回 `null`，按钮禁用，播报「提示次数已用完」 |
| 非法难度参数 | 回退 `easy`，不抛错 |

## 九、实现要点

- 引擎与页面完全解耦：引擎只依赖注入的 `random` 与 `now`，单测用固定随机源与假时钟覆盖生成、移动、暂停、超时、提示、计分。
- 页面壳复用扫雷/推箱子范式：`stateRef` + `snapshotRef` 双引用避免闭包过期；`onState` 统一驱动屏幕切换与播报。
- 迷宫墙体用位掩码（N=1 / E=2 / S=4 / W=8）存在 `Uint8Array`，渲染时逐格按位输出四条边，寻路 BFS 同一份数据，避免视觉与规则不一致。
- 单指滑动与点按共用 `moveByDir`，节流在引擎内完成，页面无需重复判断。
