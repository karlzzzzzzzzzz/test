# 连连看（Link-Link）需求文档与实现说明

> 生成于 2026-11-03，随机抽取：主页面「游戏暂停机制」→ 按任务目标替换为新游戏「连连看」；规模：小型；类型：视觉与交互优化；约束卡：与基线已知不一致点之一联动修正。
> 本文同时作为项目第 10 款小游戏（`/lianliankan`）的实现说明文档。

## 1. 背景与目标

现有 9 款小游戏均为「单局内资源/状态自洽」的玩法，缺少一款以「空间连通判断」为核心的消除类游戏。连连看用一句话规则（点两张相同图案，路径不超过两次转弯即可消除）覆盖「观察 + 触控」，单局 1~3 分钟，适合手机单手点按。

本次同时验证整条链路（随机需求 → 实现 → 推送 → 部署）能否一次走通，因此规模控制在单引擎、单路由、无后端交互。

**目标（可衡量）**：
- 新增 `/lianliankan` 路由与独立分包，首屏可交互；首页作品卡由 13 增至 14，统计条同步为 14。
- 320 / 360 / 375 / 414 / 480 / 600 / 768 / 820 / 1024 九档宽度横向溢出为 0，格子热区 ≥40×40，可见字号 ≥12px，页面 `min-height:100svh`。
- 连通判定、消除、通关、提示/洗牌、暂停与超时全部有 `node:test` 单测；`lint` 与 `build` 通过。

## 3. 页面结构

```
.llk-page
├── header.llk-top          返回首页 · 标题「连连看」· 暂停/继续
├── .llk-hud                剩余对数 · 误点次数 · 倒计时
├── .llk-live-region        aria-live polite（视觉隐藏，仅播报）
├── .llk-board-wrap
│   └── .llk-board[role=grid]  rows × 6 个 .llk-tile[role=gridcell]
├── .llk-actions            提示(N) · 洗牌(N) · 返回首页
├── .llk-hint               规则说明
├── .llk-overlay（start）    难度选择：轻松 6×6 / 挑战 6×7 / 专家 6×8
├── .llk-overlay（paused）   自动/手动暂停说明 + 继续 / 返回
├── .llk-overlay（over）     通关结算：得分/消除对数/历史最佳 + 再来一局
└── .llk-overlay（failed）   超时失败：剩余对数 + 重新挑战 / 返回
```

新增区块：整个 `.llk-page`（新路由），首页仅新增一张卡片与统计条数字。

## 4. 功能点明细

| 模块 | 交互 | 规则/逻辑 | 异常处理 |
| --- | --- | --- | --- |
| 路由接入 | 访问 `#/lianliankan` | `App.jsx` 增加 `lazy(() => import('./pages/Lianliankan'))` + `Suspense` | 加载失败由 404 路由兜底，不新增错误边界 |
| 难度与开局 | 点按「轻松 / 挑战 / 专家」 | `DIFFICULTY`：easy 6×6 / 18 对 / 180s / 基准 600；normal 6×7 / 21 对 / 150s / 900；hard 6×8 / 24 对 / 120s / 1200。图案种类 6 / 8 / 10 | 遮罩期棋盘不可点；重复开局重置全部计数 |
| 牌面生成 | 开局自动生成 | 先按「每对同图案」构造多重集，Fisher–Yates 洗牌；校验存在可消除对，不满足则重洗（上限 30 次），仍不满足则把同图案换到相邻 0/1 位强制可解 | 生成失败不影响对局，必定至少有一组可消除 |
| 选中与切换 | 点按格子（原生 button） | 首次点按选中；再点同格取消；点不同图案切换选中（**不罚分**）；点同图案且可连通则消除 | 空格、非 playing 态、暂停态点按一律忽略 |
| 连通判定 | 消除前自动判定 | 允许路径直线穿过空格、绕出棋盘外圈；转弯次数 ≤2（0/1/2 转弯均合法） | 同图案但不可连通 → 记 1 次误点、取消选中并播报 |
| 消除与计分 | 成对消除 | 两张牌置空，剩余对数 −1；通关得分 `max(100, 基准 − floor(用时秒)×2 − 误点×5)`；未通关不计分 | 分数封底 100，不为负；失败局不写最佳 |
| 自动洗牌 | 消除后自动检查 | 剩余牌面无任何可消除对时免费重排，保证存在可消除对，播报「已自动洗牌」 | 重排失败走相邻强制可解兜底 |
| 提示 / 手动洗牌 | 底部按钮 | 提示每局 3 次，返回一对可连通坐标并高亮；洗牌每局 2 次，重排剩余牌面 | 次数用尽按钮禁用；无解时提示会先自动洗牌再返回 |
| 倒计时 | 首次点按启动，HUD 每 200ms 刷新 | 剩余 = 限时 − 已用，`ceil` 显示；归零 → `failed` | 面板暂停时冻结；恢复后不补算暂停时长 |
| 暂停/恢复 | 顶部按钮；切后台/失焦自动暂停 | `visibilitychange` + `window.blur` 双触发去重；恢复需手动点「继续」 | 已结算/开始态点按暂停无效 |
| 键盘与读屏 | 方向键移动焦点，Enter/Space 选中 | 棋盘 `role=grid`/`row`/`gridcell`，roving tabindex；`aria-live=polite` 播报消除、误点、洗牌、胜负 | `prefers-reduced-motion` 关闭过渡，颜色仍可区分 |
| 成绩存储 | 通关后写最佳 | 键 `game-lianliankan-best-v1`，按难度存 `{score,time,pairs}`，仅更高分覆盖 | localStorage 不可用时结算屏提示「本局成绩未保存」 |
| 行为埋点 | 开局 / 通关 | 键 `game-lianliankan-stats-v1`：`plays/wins/pairs/timeByLevel` 全生命周期累计；脏标记 + 1s 兜底 + pagehide 落盘 | JSON 损坏回退空结构，写入失败静默跳过 |
| 首页入口与统计 | 卡片跳转 | `ENTRIES` 新增一项（`to:'/lianliankan'`、`span:'3'`）；统计条 13 → 14 | 卡片字段缺失沿用 `CardLayout` 既有降级 |
| PRD 入库 | 访问 `#/docs/lianliankan-game` | 本文件放入 `src/docs/`，在 `registry.js` 登记 slug/title/summary/date/tags/readTime | 未登记则 `/docs` 列表不出现、详情 404（既有行为） |

## 5. 状态说明

页面状态机：`start → playing ⇄ paused → over | failed`（`over`/`failed` 可经「再来一局/重新挑战」回到 `playing`）。

**三态**：
- **加载**：懒加载分包未就绪时显示 `.game-loading`「加载中…」（全局 `Suspense` 兜底）。
- **空**：尚无最佳记录时难度卡与结算屏显示「暂无」/「暂无记录」；棋盘在全空时显示空容器占位。
- **错误**：localStorage 不可用时最佳与埋点降级为内存态，结算屏追加「本局成绩未保存」，流程不中断。

**边界情况**：
1. 320px + 专家 6×8：格子约 41px，满足 ≥40px；若未来加到 7 列将跌破阈值，需重估。
2. 同一帧内先 `pause()` 再 `tick()`：以 `state==='playing'` 为准，不误判超时。
3. 最后一步消除与超时竞态：消除先进入 `over`，随后 `tick()` 因非 playing 直接返回，不覆盖胜利。
4. 快速连点同一格：第二次视为取消选中，不计误点。
5. 切后台超过限时：恢复时先回到 `paused`，不会出现「剩余 −3s」负值。
6. 提示返回的一对被玩家先消除：`hintPair` 在任意点按前清空，不会高亮已消除的格子。

## 6. 非功能需求

### 6.1 移动端

- `.llk-board` 使用 `width:100%; max-width:420px; box-sizing:border-box`，**禁止** `vw` 宽度。
- 6 列轨道 `repeat(6, minmax(0,1fr))`；格子 `aspect-ratio:1/1; min-width/min-height:40px`。
- `.llk-page` 使用 `min-height:100svh`；<768 padding 16/14/48；<480 padding 14/12/32、board max-width 340、gap 5。
- 触控：`touch-action:manipulation`、`user-select:none`，按钮 `-webkit-tap-highlight-color:transparent`。

### 6.2 无障碍

- 棋盘 `role="grid"` + `role="row"` + `button[role="gridcell"]`，roving tabindex。
- 方向键 / Home / End 移动焦点，Enter / Space 由原生 button 触发点按。
- `aria-live="polite"` 播报消除、误点、洗牌、胜负；计时器 `aria-live="off"`。
- 焦点环统一 `outline:2px solid #aa3bff; outline-offset:2px`；选中态用 `aria-selected`。

### 6.3 数据语义（约束卡 1 · 与基线不一致点联动自查）

- 基线已知不一致点为「番茄钟『今日』文案但计数是累计值」。本需求不修改番茄钟，而是把该问题作为新页面的口径自查项：页面只出现「本局」「历史最佳」与「累计（埋点）」三种口径，不出现「今日/本周」。
- `game-lianliankan-stats-v1` 的 `plays/wins` 明确为全生命周期累计值；`game-lianliankan-best-v1` 为按难度持久的最佳单局，二者互不混淆。

### 6.4 性能与埋点

- 引擎纯逻辑、无 DOM 依赖；连通判定为 BFS，单次状态上限 `(rows+2)×(cols+2)×4×3`，6×8 棋盘约 320 状态。
- 倒计时刷新 200ms；页面按需懒加载独立分包；不新增依赖。

## 7. 验收标准

1. **Given** 首页已渲染，**When** 查看作品入口区，**Then** 出现第 14 张「连连看」卡片且链接指向 `/lianliankan`。
2. **Given** 首页统计条进入视口，**When** 数字滚动结束，**Then** 「功能模块」显示 14，与入口卡数量一致。
3. **Given** 打开 `#/lianliankan`，**When** 选择「轻松 6×6」，**Then** 生成 36 张成对牌面且状态进入 playing。（主干）
4. **Given** 两张同图案牌位于同一行且中间全空，**When** 依次点按，**Then** 两牌消除、剩余对数 −1、播报更新。（主干）
5. **Given** 两张同图案牌被其他牌完全围住，**When** 点按第二张，**Then** 记 1 次误点并取消选中，牌面不变。（异常）
6. **Given** 玩家清除最后一对牌，**When** 消除动作完成，**Then** 进入通关遮罩，得分 = `max(100, 基准 − 用时×2 − 误点×5)`。（主干）
7. **Given** 提示次数已用尽，**When** 再点「提示」，**Then** 按钮为禁用态且棋盘无高亮。（异常）
8. **Given** 游戏进行中切到后台 10 秒，**When** 回到前台，**Then** 计时冻结在切走时的值，需手动点「继续」。（异常）
9. **Given** 倒计时归零，**When** 触发 `tick`，**Then** 进入超时遮罩，剩余显示 00:00 且不写最佳记录。（异常）
10. **Given** 视口 320px 与 375px，**When** 检查页面，**Then** `scrollWidth − clientWidth = 0`，无越界元素，按钮热区 ≥40×40，可见字号 ≥12px。
11. **Given** 仅用键盘，**When** 用方向键移动焦点并按 Enter，**Then** 目标格被选中，`aria-live` 播报选中/消除结果。
12. **Given** 系统开启「减少动画」，**When** 消除牌面，**Then** 无过渡动画，选中/提示态仍以颜色区分。
